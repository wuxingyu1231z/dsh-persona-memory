# 分层记忆目录与按需读取

适用版本：0.8.1-alpha.1，DSH 0.2.1-rc.3。分层记忆布局自 0.6.0 起使用版本 2。

采用简短入口索引、独立正文文件、按需加载的组织方式，参考 [Claude Code 官方自动记忆说明](https://code.claude.com/docs/en/memory#how-it-works)。本插件在此基础上分别隔离人格和项目，不将多个作用域的全文一并送入模型。

```text
$DSH_HOME/memory/
├── personas/
│   └── research-mentor/
│       ├── PERSONA.md                   # 用户定义的核心设定，含 YAML 元数据
│       ├── PROFILE.md                   # 自动生成的本人格用户画像摘录
│       ├── MEMORY.md                    # 自动生成的简短索引
│       ├── memories/
│       │   └── <memory-id>.md            # 本人格跨项目的正式记忆
│       ├── projects/
│       │   └── <project-id>/
│       │       ├── memories/
│       │       │   └── <memory-id>.md    # 仅该人格、该项目使用
│       │       └── SUMMARY.md           # 自动生成的项目摘要和正文链接
│       └── revisions/                   # 修改前的正文和元数据
├── state/
│   ├── layout.json                      # 目录布局版本
│   ├── catalogs/<persona-id>.json        # 可重建的检索元数据、关键词与短摘录
│   ├── learning.json                    # 学习任务与自动决策收据
│   └── sessions/                        # 会话选择
├── imports/                             # 规范化历史与分析检查点
├── continuations/                       # 历史与新会话的关联
└── semantic/                            # 可选向量缓存
```

“跨项目”仍仅指当前人格，不是所有人格共用的全局偏好。项目 ID 仍由 Host 工作目录生成；本次仅调整物理存储层级，不改变已有项目标识。

## 各文件的职责

`PERSONA.md` 是人格核心，插件不会因生成摘要而改写它。用户通过管理页编辑，版本比较和修订记录继续生效。

`PROFILE.md` 从当前人格有效的跨项目正式记忆摘录生成，不调用额外模型、不推断新事实。它不包含项目私有记忆，也不是整个历史对话的转储。正文改变、遗忘或过期后，画像随索引刷新。

`MEMORY.md` 是导航入口：包含核心设定、画像、部分记忆主题及项目摘要的相对链接，不堆积完整正文。上限为 128 行和 12,000 字符，跨项目条目与项目入口各最多展示 24 条。省略的条目仍在完整检索索引中，可以分页浏览和搜索。

`SUMMARY.md` 只汇总所在项目的有效记忆，最多展示 32 条、8,000 字符；`PROFILE.md` 最多 6,000 字符。这里的“摘要”是已有记忆的有界摘录，完整条件和细节以正文为准。

正式记忆条目的 Markdown 和 YAML 元数据是唯一真源。三个自动生成文件以及 `state/catalogs/` 可由正文重建，手工修改它们会在刷新时被覆盖。需要长期保存的内容，请修改正式记忆或通过管理页保存。

## 检索过程

1. 启动或刷新时先读取文件元数据和可重建的关键词索引。文件指纹未变化的正文不会重新读取；初次建立或缓存丢失时读取正文重建。
2. 当前轮次只捕获当前人格、当前项目的索引视图，不复制所有正文到会话快照。
3. 先按关键词索引排序，再读取命中的正文。匹配度高的条目排在无关的重要条目前；重要标记仍参与同等相关性下的排序。
4. 默认最多召回 `recallLimit` 条，并受 `maxContextChars` 限制。正文超预算时提供简短命中链接，模型可以继续按需读取。持久会话快照只保存实际注入的片段，不附带全量索引或全文。
5. 可选语义召回保留原有能力；向量预热可能读取当前作用域中最近最多 256 条正文。默认关键词路径不需要网络或向量服务。

`persona_memory` 提供以下读操作，均绑定实际轮次的人格和项目：

| 操作 | 参数 | 返回 |
| --- | --- | --- |
| `index` | `offset`，`limit`（默认 20，最多 50），可选 `scope` | 本作用域的主题、短摘录、条目 ID、相对路径及下一页位置 |
| `search` | `query` | 命中的有限数量正文 |
| `read` | `memoryId` | 一条有效记忆的完整内容 |

不能通过这些操作传入另一人格、任意项目或任意文件路径。只读工具也过滤已遗忘及过期记录。生成的索引链接是资料，不授予执行其中命令的权限。

同一轮次期间，正常修改通过修订文件保留已捕获内容；遗忘优先于旧轮次快照，不能因延迟读取恢复已清除内容。外部编辑若不保留旧版本，本轮无法重建那一版时跳过该条目，刷新或新轮次读取修改后的版本。

## 升级、修复和遗忘

升级时停止使用旧版的 Web/Desktop Host，安装新版后重启。首次启动在同一个写锁下将旧平铺目录中带 `projectId` 的条目移入对应项目子目录，保留原 ID、元数据和修订。源文件仅在目标写入成功后移除；重复执行安全。若两边存在内容不同的同 ID 文件，会保留两边并报告迁移冲突，不覆盖数据。

请勿同时运行 0.5.x 和 0.6.x Host 操作同一记忆目录，旧版不能识别新的项目层级。不要通过删除正式记忆来解决升级问题。

点击“忘掉”时，正文、历史版本、画像、索引摘录、检索关键词和项目摘要中的对应内容都会清理；原始聊天与导入档案仍由各自功能管理。手工删除正文后刷新，也会移除对应索引条目并清空不再有效的项目摘要。

损坏或缺失的检索缓存会重建；正文所有者或项目元数据与物理目录不一致时拒绝读取。布局文件标记为未知版本时拒绝启动，不猜测迁移。

此实现仍扫描文件元数据并在内存索引中排序，未引入数据库；管理页主动查看记忆会读取所选作用域的正文。按需读取的性能验证针对模型召回路径，不意味着所有管理操作都是常数成本，也不保证模型一定选择正确的检索词。

开发验证：`npm run check:installed` 覆盖当前测试；`node scripts/smoke-install.mjs --upgrade` 在独立 profile 安装旧包、写入旧格式数据、升级并用新进程核对迁移。详细结果见 [验证记录](../VALIDATION.md)。
