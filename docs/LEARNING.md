# 学习、自动记忆与校验

当前版本为 0.8.1-alpha.1。人格与 Markdown 文件兼容旧版本；旧待确认记录在启动时自动处理，可靠内容保存、过时或受锁定保护的冲突跳过，无需用户逐条确认。逐条过期时间输入和对应保存按钮已从界面移除；旧文件的过期元数据仍按原规则读取。

## 日常使用

在侧栏「人格与记忆 → 人格与记忆管理」选择要管理的人格及学习方式：自动学习、仅明确偏好或暂停。默认自动学习。普通聊天在轮次结束后由模型提取可靠的长期事实和偏好，直接保存或更新；不再等待三条证据，也不需要用户逐条确认。仅明确偏好模式仍会过滤模型推断。

模型输出必须附有逐字匹配的用户证据。临时要求、假设、引用、无依据的猜测及助手自己说的话不保存。模型识别到当前用户的新偏好后，可更新同主题未锁定旧记忆。新旧比较依据原始证据时间，旧历史和后台晚到的任务不能覆盖更新的信息；同样的内容被再次确认时更新证据时间，避免后来的旧导入覆盖它。

人格核心不会被自动修改。表达风格、指导习惯等通过对应人格的偏好记忆逐渐改变行为。锁定后，后台和模型工具不能自动覆盖；需要先在界面解锁。过期条目仍保留文件与历史，但不再作为有效记忆召回，不会按时间删除稳定偏好。

正式记忆现在按人格与项目分目录，索引、用户画像和项目摘要随保存/纠正/遗忘更新；详见 [存储说明](STORAGE.md)。

## 对话内工具

`persona_memory` 提供分页 index、按 ID read、search、remember、forget。调用不能指定人格或项目 ID，归属由实际轮次绑定。写入需要本轮用户的确切原话；遗忘还需要在请求中明确指出记忆主题，并使用搜索得到的版本。无法可靠定位时可在界面操作。

暂停只影响后台学习，不阻止用户明确保存。点击遗忘会清除正式条目的正文、旧版本及对应决策证据，记录来源排除，并取消该范围内早于操作的未完成学习任务。原始聊天及已记录的会话快照仍由 Harness 保存；遗忘不等于删除聊天。

## 重启、排队和恢复

用户消息入队时，在原消息来源元数据中记录人格 ID，保持消息 ID、角色与正文。第一条消息被该轮领取时确定人格；之后的 UI 切换不改变本轮。处理完一轮才从原始、已提交的用户消息创建任务，并同时保存处理游标，避免反复提取整个历史。

任务、自动决策收据和学习模式保存在 `state/learning.json`。任务含有原始人格、项目、消息 ID、发生时间与当时的模型路由。新 Host 可恢复待处理任务；多个 Host 通过所有者租约避免重复执行。处理失败后按配置重试，达到上限时显示失败，用户可点击重试。成功后清除任务中的原始输入，只保留必要证据与收据。失败的任务保留输入用于重试。

后台提取默认最长 60 秒、最多 3 次尝试；取消或卸载会中止辅助调用并等待其结束。辅助模型必须支持取消，恢复时相同模型路由也必须可用。来源去重防止重试增加证据票数；版本比较和来源时间防止较晚完成的旧任务覆盖用户的新修改。

Markdown 写入与学习状态通过同一文件锁协调。正式记忆写入与状态收据不是跨文件原子事务；发生中断时，通过学习 ID、已有内容与版本比较对账，中断后的决策收据由启动恢复或任务重试自动对账，不承诺磁盘掉电后的事务级持久性。文件锁采用心跳，孤立锁过期后可恢复；各 Host 需要一致的锁配置。

## 项目校验

按 [配置示例](../examples/verification.cordis.patch.yml) 设置 `verificationChecks`。`persona_verify` 只调用这些配置项，不从记忆文本生成可执行命令。子工具调用仍经过 Harness 工具策略、审批和取消流程；不会另开不受管理的 shell。

只有所有适用检查都返回数字退出码 0 时标为 passed；非零为 failed，缺少配置、权限被拒绝、超时或没有可判定退出码时为 blocked；尚未调用时为 not-run。结果随实际工具输出和持久上下文记录。会话中的校验提示依据执行结果，不采信助手自述；未运行时省略提示。

默认 `exitCodeField` 为 `exitCode`，可适配其他工具的字段名称。后台任务型工具若仅返回任务 ID、不返回最终退出码，不能直接当作通过。默认不配置具体命令，避免在未知项目中运行不合适的脚本。

## 配置字段

| 字段 | 默认值 | 含义 |
| --- | --- | --- |
| learningMode | auto | 新人格的默认后台学习方式，个人格设置优先 |
| inferredEvidenceCount | 兼容旧配置 | 已不参与自动记忆决策 |
| learningTimeoutMs | 60000 | 单次辅助调用时间上限 |
| learningMaxAttempts | 3 | 自动尝试次数上限 |
| learningPollMs | 2000 | 队列检查与重试的基础间隔 |
| learningInputChars | 16000 | 每次学习请求的输入字符预算 |
| learningOutputChars | 16000 | 提取结果字符上限 |
| learningMaxTokens | 2048 | 辅助模型的输出 token 上限 |
| lockStaleMs | 30000 | 文件锁的过期时间 |

长消息会分段处理，每个分段仍使用同一个原消息 ID，不能把多个分段当成多次独立偏好证据。当前实现每个分段调用一次模型。0.3.0-alpha.1 已加入历史导入、续聊与可选语义召回，见 [第三阶段说明](IMPORT.md)。
