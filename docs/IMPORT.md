# 历史导入、人格提取与续聊

适用版本：0.8.6-alpha.1，兼容 DSH `>=0.2.1-rc.3 <0.3.0-0`。Web 与 Desktop 使用相同界面，在浏览器/桌面所在设备本地预处理文件，再经 Harness 既有连接自动分批存到 Host 的 memory 目录。远程部署的归档保存在远程 Host。

## 操作

1. 点击侧栏「人格与记忆」，进入独立管理页的「历史导入与续聊」。选择已配置的模型服务与模型，无需先创建会话。需要项目记忆或项目续聊时，在「记忆范围」选择对应项目。
2. 可直接点击该页「新建人格」，填写名称、简介及设定，创建后自动成为导入目标。它不切换现有聊天的人格，也不需要文件或模型。选择 `.json`、`.md` 或 `.markdown` 后自动预处理并导入**文件内全部会话**，无需勾选会话。这一步不调用模型。已保存的整包文件可以从“已保存的导入”重新打开。
3. 选择对话和分支，查看原文、原始时间与导入提示。预览每页 50 条，单条超过 6000 字符会截短显示，归档仍保留完整正文。
4. 点击“提取当前分支”，或勾选多个分支后“提取所选分支”。界面显示预计调用量及当前处理步骤。前端自动逐步请求，每次只处理一个新分析段或汇总节点，结果随完成随保存，避免整批提取一直占用一个连接。单步最长四分钟，模型自身超时限制仍适用；取消或断线后再次提取会复用已保存的分段和汇总。完成后查看续聊摘要、提取偏好及逐字依据。
5. 选择已有的人格，或“根据历史新建人格”。新人格的名称、介绍与设定草稿均可编辑，ID 使用小写英文、数字、下划线和短横线。点击“应用当前分支”或“合并所选分支”，可靠记忆自动保存到目标人格；不再进入待确认列表。
6. 可在「人格与记忆管理」查看自动保存的结果；需要时纠正、忘掉或锁定，不需要逐条采纳。
7. 在“新对话的历史上下文”选择摘要或完整模式，再在按钮上方的“续聊工作区”选择分组，点击“新建对话并续聊”。界面打开一个独立的 Harness 对话，原会话不增加历史消息。输入下一句话即可继续。

不同话题可以分别应用到不同人格；多个相关对话可以合并到同一人格。续聊一次对应一个选定分支，不会把不同分支拼成一条虚构对话。**全部会话已在文件选择时导入**；“批量提取记忆”的勾选仅控制本次模型分析，单次最多 32 个分支。当前版本以分支为分配单位，不在单个分支内部自动按话题拆分多个人格。导入归档不会自动创建几百个原生聊天；需要续聊时再创建对应的独立聊天。

## 本地预处理与整包保存

DeepSeek 仅保留 REQUEST / RESPONSE 的完整正文；移除 THINK、搜索及工具活动、附件本体。ChatGPT 保留用户和助手可见文本，移除结构化 analysis/commentary 推理通道、面向工具的助手消息、系统/工具角色及非文本附件。保留图节点、父子关系、原会话/消息标识和可识别时间；不同分支保持独立。代码、正文长度不被擅自压缩。Markdown 缺少结构化通道标记时保留角色正文，不猜测删除思考段，以免误删用户内容。

文件在本地清理后，分支较多的单个会话先自动拆成每组最多 16 个分支的传输记录。每个分支保留完整共享前文、原始标识、时间和原选中状态；不会把不同分支拼成新对话。随后按每片最多 32 条传输记录、128 条分支、约 200 万原始字符，并结合分支展开后的 20,000 条消息和归档体积预算继续分批。多个分片可以属于同一个源会话，完成后仍提交为一个整包归档。传输时每个逻辑分片再按 JSON 转义后的 UTF-8 大小拆成不超过约 60 KB 的小片（含请求封装低于 64 KiB），单个长会话也会自动拆传输。短暂连接失败自动重试最多两次；小片落盘可重放，收齐后才解析逻辑分片。Host 再次验证并暂存，全部分片数量与分支数量一致后，才提交一个整包归档。重复分片可重试；相同整包重复导入合并为同一归档。存在坏图、无法解析的会话、超限或冲突标识时整包报错，不会静默只导入一部分。界面显示处理数量和进度。

本页内取消或连接失败，可用「重试整包导入」复用分片进度。刷新页面后可重新选择原文件；已完成整包仍会去重，但旧的未完成暂存不自动清理。`memory/imports/upload-*.json` 为上传收据，`part-*.json` 为未完成正文；成功提交后删除其分片正文，收据不含原文。未完成暂存不出现在归档列表。它们可以在停止 Host 后手动清理。

需要先生成清理版文件时，可使用包内离线命令（Node 24）：

```powershell
node bin/preprocess.mjs "C:/path/to/deepseek_data-export" "D:/path/to/new-cleaned-folder"
# 也接受 conversations.json 或角色标记 Markdown 的文件路径
```

安装 npm 包后也可使用 `dsh-memory-preprocess <源文件或目录> <新输出目录>`。目录输入只读取 `conversations.json`，不读取 `user.json`。输出一个包含全部会话的 `conversations.cleaned.json` 与 `report.json`（数量、大小、清理统计和 SHA-256）；Markdown 输出单个 `.md`。输出目录须为不存在的新目录，不覆盖原始导出或旧产物。清理版可直接在插件页整包导入。

## 支持的文本结构

| 输入 | 识别方式 | 限制 |
| --- | --- | --- |
| DeepSeek JSON | 会话 `mapping` 图，节点 `message.fragments` 中的 `REQUEST` / `RESPONSE` | 读取可见用户与助手正文；忽略 THINK、FILE 和其他活动 |
| ChatGPT JSON | 会话 `mapping` 图、`author.role`、`content.parts`、`current_node` | 主分支与其他叶子分支分别预览，优先原选中分支 |
| 通用 JSON | 单个对象或数组，`messages` / `chat_messages` 中明确的 `role: user / assistant` 与 `content` | 支持字符串或文本 parts；不猜测不明角色 |
| Markdown | `## 用户` / `## 助手`、`## User` / `## Assistant`、`**User**`，或 `User:` / `Assistant:` | 代码围栏内的角色标题不会分割消息；无可靠时间时标为未知 |

JSON 顶层可为单会话、会话数组或 `{ "conversations": [...] }`。不同导出工具可能改变格式；无法识别时会说明所需结构，不会静默假定角色。当前没有 ZIP 解压、HTML 解析、图片/音频/文件恢复或隐藏思考过程迁移；不能保证覆盖所有平台或第三方导出变体。可以参照 [Markdown 示例](../examples/history.md) 转为角色标记文本。

## 记忆与人格规则

人格风格草稿参考历史对话的表达方式；用户事实只能从真实用户消息的逐字依据产生。记忆保存时再次核对来源与周边原文，排除明显临时、假设或引用。助手说“你喜欢什么”本身不能成为记忆证据。

应用历史时由模型选出的可靠长期信息自动保存或更新，无需逐条确认。来源去重避免反复导入生成重复记忆。项目记忆归属管理页选择的项目；未选择项目时会跳过项目偏好并提示，不会降格为跨项目偏好。

冲突使用原始证据时间判断，不以导入时间冒充最新信息。已锁定内容和更新的证据受保护。缺失日期时保持未知时间；同一分支内同主题以最后一条有依据的用户表述为准，跨来源日期不明的冲突保留已有内容。已有的人格核心设定不会因合并记忆被自动改变。

模型可能误解内容。管理页保留纠正、忘掉和锁定操作，不再要求用户维护待确认队列。

## 新对话如何继续

从独立管理页创建的新会话使用该页选择的模型、人格及 Harness 当前默认能力预设。“续聊工作区”独立决定新会话的分组与工作目录，不改变页面顶部的记忆范围。上方记忆范围只决定管理和提取偏好写入哪个项目。

下拉框列出 Host 当前工作区的名称与目录，优先选中宿主持久记录的默认工作区，重命名或重排默认工作区也不会丢失选择。旧环境缺少默认标识时依次识别默认名称/目录、Host 默认目录、首个工作区；没有工作区时选“未分组”。工作区列表随管理页加载读取；若原工作区已删除，需重新选择，不能静默改到其他分组。新增工作区通过 Harness 原生工作区入口操作。

选择工作区时采用其实际目录，并持久调用宿主的会话归属能力，重启后仍在该分组。选择“未分组”时使用 Harness 默认工作目录（缺少目录服务的精简环境使用用户主目录），即使该目录匹配某个工作区也不自动归组。工作区已删除或目录不可用时，在创建会话前报错。归属写入失败时保留历史，允许相同请求重试，不把失败标记成已完成。

管理页不会创建隐形辅助会话。旧版绑定会话 API 未传 workspaceId 时保留继承源会话目录/分组的行为；新版调用可传具体工作区 ID，null 表示主动未分组。能力和权限仍由当前 Harness 配置决定。旧系统提示、旧工具调用及执行结果不会重放，也不会自动运行历史中的请求。

历史用户与助手消息以原生事件顺序保存，原始时间另行标记。历史助手内容可在聊天界面显示；创建本身不会触发模型回复。新提交的第一条消息按已有历史轮次继续编号，之后可以正常切换人格、学习新偏好与校验项目。导入的旧消息带来源标记，不会在续聊时再被当成刚发生的用户偏好重复学习。

- **摘要模式（默认）**：短历史直接保留全文上下文；超过预算时向模型发送提取的摘要和近期正文片段，并标记截短部分。完整原文仍保留在归档与会话日志中。
- **完整模式**：全文进入模型上下文，超过配置预算会拒绝创建并建议改用摘要。模型自身的上下文限制仍可能更小。
- `persona_history`：只查当前续聊所关联的原文归档。支持关键词与分页，返回有限长度的文本片段、角色、原始时间及截短标记。它补查细节，不执行归档命令。

创建记录先落盘，成功后返回新会话 ID；连接失败后的相同请求重试返回同一 ID，避免误建多个窗口。会话走 Harness 自带存储，重启后可通过普通会话列表恢复。用户主动再次创建可以得到另一条独立会话。

0.7.2 修复旧版在未选择项目时创建无 `cwd` 的续聊：DSH 0.2.1-rc.3 的历史 `page` / `follow` 会主动拒绝这类会话，即使日志已保存，也会报告 `session/not-found`。现在显式项目优先；否则使用 Host 默认工作目录（精简环境缺少目录服务时使用用户主目录），并在确认存储可见后才标记创建完成。实际目录和历史模式参与新版续聊身份计算，不会复用旧版错误的完成收据。

旧版已创建的失败入口保留原样。更新并重启后，回到已保存的导入，打开原分支，点击「新建对话并续聊」创建可读取的新入口即可；不必重导文件或重做已经完成的提取。该过程保留旧日志和原始归档，不直接修改宿主会话的不可变元数据。新会话后续项目记忆按其实际工作目录隔离；历史提取应用时，项目偏好的目标仍由管理页选择决定。

## 分段、取消和配置

提取使用管理页单独选择的模型，会增加调用与费用；无需重复填写 API 密钥。长文本先分段摘要，再逐层合并；已完成的分析段作为检查点存盘。取消、离开管理页或断开连接会中断当前任务。再次选择同一文件/归档并提取时复用完成段；改变模型、提取提示或预算会使对应缓存失效。中断时尚未完成的段及摘要合并步骤需要重做。

默认限制如下，单位均为字符或条数，不是 token：

| 配置 | 默认值 | 用途 |
| --- | ---: | --- |
| `importMaxChars` | 4000000 | 单个自动传输分片的字符数 |
| `importMaxConversations` | 128 | 单分片规范化会话/分支总数 |
| `importMaxBranches` | 16 | 每条传输记录的分支选择数；原会话超过此数时客户端自动拆批 |
| `importMaxMessages` | 20000 | 单分片规范化正文消息总数（含分支共享前缀） |
| `importInputChars` | 16000 | 单次提取输入预算，含结构化信息 |
| `importSummaryChars` | 4000 | 续聊摘要上限；单段最多 2000，实际还受输入预算约束 |
| `importMaxChunks` | 200 | 单个分支的最大提取分段数 |
| `continuationChars` | 24000 | 初始历史上下文预算，范围 8000–96000 |
| `importMaxTokens` | 8192 | 历史提取初次输出 token 预算；一次自动重试翻倍，最多 32768 |
| `importTimeoutMs` | 180000 | 历史提取每次模型请求超时；与后台学习独立 |

本地原始文件硬上限 64 MB / 6400 万字符、10,000 个源会话及 200,000 个图节点；整包最多 10,000 条分支，Host 规范化暂存合计最多 6400 万字符。单个会话超过 16 个分支会自动拆批；有源会话标识的图会按所选分支保留对应祖先节点。匿名图保留身份计算所需的完整图，避免拆批改变标识。若单个分支的完整正文仍无法放入一片，或整包超出总体资源上限，则明确报错，不截断正文。自定义更小的 Host 分片限制可能导致验证拒绝。大文件也受 Harness 传输层和设备内存限制。摘要预算只控制导入历史部分，不包含后续人格、项目上下文、工具说明和新的对话。分析目前以手动开始和重试恢复为主，不在导入或重启后自动调用模型分析所有归档。

## 提取失败与重试

0.7.1 起识别 DSH 模型流的结束状态：服务失败报告 HTTP 状态（若有），取消或超时直接停止，达到 token 上限按截断处理，缺失结束状态按流中断处理。不会把空响应、错误响应或截断 JSON 当成成功结果存盘。空正文、截断、流未完成或不符合格式的 JSON 最多自动重试一次，重试重新生成完整对象并增加输出预算，可能增加一次模型调用。网络/服务失败和超时不自动重试。失败后直接重新提取即可复用已完成分析段，无需重导文件。模型原始失败消息可能包含凭据或正文，因此界面不直接回显。

## 可选语义召回

默认没有嵌入请求。参考 [配置示例](../examples/embedding.cordis.patch.yml) 手动启用已准备好的 Ollama 或 embeddings 兼容服务，不会自动安装或下载模型。Ollama 使用官方 `/api/embed` 协议；兼容接口使用 `input` 数组及带 `index` 的 `data[].embedding` 响应。

只对当前人格和当前项目范围内的有效、未过期记忆生成向量；不会将所有人格一起发送。每次最多考虑最近更新的 256 条有效记忆，按批次缓存，查询截取最后 8000 字符；与关键词排名融合。服务异常、维度不一致、凭据缺失等情况下回退关键词。凭据通过指定的环境变量读取，不写入向量文件。

`semantic/` 是可删除重建的缓存，条目包含记忆 ID、内容哈希和向量，没有正文或密钥。修改记忆使哈希失效；遗忘会清掉对应缓存，生成中的旧向量不能在遗忘后重新落盘。缓存按模型端点、人格和项目隔离。

## 存储与验证边界

人格及正式记忆仍用 Markdown；0.6.0 起项目记忆位于本人格 `projects/<project-id>/memories/`，摘要和索引自动更新，见 [存储说明](STORAGE.md)。规范化历史、摘要与分析检查点位于 `memory/imports/<batch-id>.json`，续聊关联位于 `memory/continuations/<session-id>.json`。源文件中的正文会持久保存；不支持在界面删除整个导入批次，暂可在关闭 Host 后管理归档文件。遗忘一条记忆不会删除原始档案或既有会话。

通过 DSH 0.2.1-rc.3 实际安装运行时的副本执行 AgentLoop、Gateway、JSONL 持久化重启验证，提取模型和 embeddings 请求使用确定性模拟响应。尚未完成真实模型准确率评估、Desktop 原生窗口安装和实际浏览器端到端验收。支持范围为 DSH `>=0.2.1-rc.3 <0.3.0-0`，最低开发基线为 rc.3；多版本结果见 [验证记录](../VALIDATION.md)。


## 模型返回格式与自动缩小分析段

0.8.6 使用合法 JSON 示例及明确的字段、枚举和长度要求。解析时允许单个完整 JSON 对象外的代码围栏或说明文字，不补写被截断的 JSON，不推测缺失字段，不采纳多个对象中的某一个。JSON 语法错误、字段格式错误、输出超限、空响应、流中断和模型服务错误分别报告；字段诊断仅包含受控字段路径与错误类别，不回显模型原文或凭据。

无效输出先自动重试一次，重试包含具体字段诊断。长分析段仍失败时，保存拆分计划并自动缩小该段后继续；已完成的分析段与汇总保留，原始归档正文不变。自动缩小仍受 `importMaxChunks` 上限约束，输入已很小仍无效时报告失败段序号，不会无限拆分。模型服务错误、鉴权失败及用户取消不会触发内容拆分。汇总结果继续使用检查点和有界重试。
